# 日本版Web相談・音声・通知

`src/web-consultations.ts` は、Supabaseで確認済みのWeb会員だけに既存の相談・無料枠・鑑定Workerを提供する。LINEの署名検証と別に、Web APIはSupabase Authと会員RPCを毎回検査する。日本市場以外と、停止・削除依頼中の本人は拒否する。

012は相談の配信先と本人対応表、単回のLINE連携、永続的な回数制限、本人通知を追加する。013は任意通知とOutboxを追加する。旧相談にはline配信先が既定で入り、010の保留を解除しない。新しいコードは配備前に012の必要な列・表を確認する。アプリ起動の既存migration処理で順番に適用する。007/008を再実行してはいけない。

Web相談は共通の確認処理で無料回数・購入済み利用枠を予約する。3件目以降の支払い待ちはStripeを読み取って再照合する。支払い用の価格・アカウント・既存LINE向けWebhookを変更しない。Webの結果と支払い確認をLINEへpushしない。

LINE連携は、自分のWeb画面で発行したコードをLINEへ送り、LINEで明示的に承認する。対応表を別アカウントに付け替えない。利用開始済みのWeb会員と既存LINE会員の自動的な統合は提供しない。相談本文・利用枠・購入権利を無条件に移し替えない。

録音は2分・10MBまで。原音は保存せず、原文を安全確認してから編集可能な下書きへ進む。音声の文字起こしにはOpenAIのAPI料金がかかり、実時間が2分を超える場合はプロバイダー応答後にも拒否する。

Web内の通知、任意Push・メール、DB Outbox、最大6回の再試行、7日集計を実装する。停止・削除・メール変更を、会員DBの同意資格を使って配送直前にも確認する。本文や鑑定は通知へ載せない。SMTP・VAPID秘密値はRenderだけに置き、GitHub Actionsは専用の短期OIDCで通知処理を依頼する。

`WEB_CONSULTATION_ENABLED` は接続・DB・配備が揃うまで有効にしない。既存のRender Cron追加は不要。台湾・韓国のブランチとサービスを今回の日本版変更で更新しない。実メール・本人MFA・実機録音・Push受信・実Stripeライフサイクルは別に確認する。
